# 项目状态与四级 ID

## 核心原则

每个项目只维护一份机器可读的 `project.json` 作为事实源。Markdown 分镜、提示词、HTML 报告和质检结果都从它派生；不得在多个文件中分别维护互相冲突的角色、镜头或状态。

新项目使用四级 ID：

| 层级 | 格式 | 含义 |
|---|---|---|
| Beat | `B01` | 一次目标、障碍、尝试、结果或价值变化 |
| Shot | `S01` | 一个画面任务、一个主体动作、一种主运镜 |
| Clip | `C01` | 一次 AI 视频生成，可含一个或多个连续 Shot |
| Asset | `A-CHAR-01` 等 | 角色、场景、道具、服装、风格或参考资产 |

关系为：`Beat 1..n -> Shot 1..n -> Clip 1..n`。Shot 必须指向一个 Beat；Clip 必须列出按顺序包含的 Shot；提示词、生成结果、版本和质检必须使用相同 ID。

## 项目状态最低字段

- 项目：ID、名称、画幅、目标时长、平台或平台中立、不可改变事实。
- 资产：ID、类型、来源、主要用途、硬锁定、可变项、有效时段、禁止迁移内容。
- Beat：目标、障碍、尝试、预期、结果、价值变化、节奏和预算。
- Shot：Beat ID、画面任务、导演意图、主视角、视角所有者、镜头身份、凝视目标、成立证据、景别机位、站位轴线、主体动作、主运镜、起点、终点、入口/出口锚点、台词 ID、资产 ID。
- Clip：Shot ID 列表、模式、预计时长、平台档案、参考调度、时间脚本、提示词版本、必须发生、不得发生、末帧交接、定向稳定约束、状态、实际终点。
- 生产状态：`planned`、`prompt_ready`、`generated`、`accepted`、`rejected`、`post_fix`。
- 来源对白：为需要逐句保留的文本分配 `D001` 等 ID，并记录由哪个 Shot 承载。

使用 `assets/project-state-template.json` 新建项目。写入或修改后运行 `scripts/validate_project.py`。

## 状态更新纪律

1. 先更新 `project.json`，再生成提示词或报告。
2. 只有 `accepted` Clip 的实际终点进入正式连续性。
3. `rejected` Clip 不得作为后续来源。
4. 修改只影响相关 Shot/Clip；保留旧提示词版本和失败原因。
5. 后续 Shot 在前一 Clip 接受前保持暂定。

## 旧 Uxx 项目兼容

读取旧项目时不要直接丢弃 `Uxx`：

- 若一个 U 只有一个镜头和一次生成，映射为同序号 Shot 与 Clip，例如 `U03 -> S03 + C03`。
- 若一个 U 内有多个镜头，拆成多个 Shot，再保留一个或多个 Clip。
- 在迁移记录中保存原 U ID；完成映射后，新输出只使用 B/S/C/A。

检查方法：任意生成文件能否回到唯一 Beat、Shot、Clip 和 Asset？若不能，先修复状态映射，不继续生成。
