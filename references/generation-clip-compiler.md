# Shot 到 Clip 编译与平台适配

## 两层设计

先执行 `prompt-bible.md`，再完成平台中立的 Shot 合同和 Clip 时间脚本，最后编译平台提示词。平台限制只能改变分组和措辞，不得反向改写剧情事实与导演意图。

## Shot 合同

每个 Shot 固定：画面任务、导演意图、主视角、视角所有者、镜头身份、凝视目标、成立证据、构图机位、站位轴线、主体动作、主运镜、起点、终点、入口/出口锚点、台词和资产映射。客观观察视角可使用中性叙事观察者；其他视角按 `viewpoint-and-gaze-design.md` 写完整合同。

## Clip 分组

满足以下条件时可把连续 Shot 合入一个 Clip：

- 同一地点或连续子区域。
- 主要角色和资产集合稳定。
- 情绪、动作和摄影逻辑连续。
- 能在目标平台一次可靠生成内完成。
- 合并后仍能清楚写出内部 Shot 顺序与时长。

出现地点硬切、角色集合变化、关键道具独立揭示、情绪/权力大转折、参考资产切换或动作密度过高时拆 Clip。不要因为镜头变化就机械拆成多个短生成。

## 跨 Clip 转场

特殊转场按 `transition-design-and-cut-bridges.md` 建立合同。若转场跨越两个 Clip：

- 前 Clip 写明退出状态、主匹配条件、隐藏剪切窗口和实际可交付尾帧。
- 后 Clip 写明进入状态及必须继承的方向、速度、动作相位、屏幕位置或比例。
- 将场景、时间、服装等允许变化项与身份、方向、动作阶段等保持变量分开。
- 平台无法可靠一次生成换景时，分别生成稳定尾部和头部，把转场交给后期剪辑。
- 接受成片后以实际尾部状态更新下一 Clip，不继续使用已经失真的计划状态。

## 平台档案

平台未指定时保持平台中立，不写模型名、专属标签和固定时长。用户指定平台时建立本项目平台档案：

- 平台/模型/入口。
- `last_verified` 日期和信息来源。
- 支持模式：文生视频、图生视频、首尾帧、参考视频、编辑、延长等。
- 时长、画幅、参考数量、字符或字段限制。
- 音频、对白、字幕和人物授权边界。

这些信息变化快；需要精确平台事实时先核实，不把临时参数写入通用规则。

## Clip 提示词

按提示词圣经编译：Clip ID/版本 -> 参考调度与硬锁定 -> 必须发生/不得发生 -> 覆盖全时长的内部 Shot 时间脚本 -> 准备/执行/落定 -> 声音 -> 连续性 -> 末帧交接 -> 最多三条定向稳定约束。

关键图仍按 Shot 负责静态起点；视频提示词按 Clip 负责时间过程。一个 Clip 包含多个 Shot 时，每个 Shot 保留 ID 和内部时间，不合并身份。

## 编译检查

- Clip 时长是否符合当前平台档案，而不是通用固定值。
- 内部 Shot 时长之和是否与 Clip 时长一致。
- 已完成 Beat 是否被重演，未来 Beat 是否提前泄露。
- 对白 ID 是否只出现一次且说话人明确。
- 下一 Clip 是否从上一接受 Clip 的实际终点成立。
- 特殊转场是否有合同；切点窗口、主匹配条件和前后状态是否可执行。
- 跨 Clip 时保持变量是否分别写入前 Clip 尾部与后 Clip 头部。
- 每个时间段是否写明主体、空间、动作阶段、视角机位、主运镜和终点；是否覆盖全时长且不重叠。
- 拼接是否存在重复帧、冻结、闪屏、动作复读或声音重叠。
- 稳定约束是否针对当前风险且不超过三条。
